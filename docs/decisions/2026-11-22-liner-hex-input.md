# ライナー・入子の色指定に HEX 入力欄を追加する（v24.1 に含める）

## 背景

v24.1（ライナー・入子のカラー指定）の iPad 実機確認で、麻地の色・金属の色の入力が色選択UI（`<input type="color">`）だけであり、
iPad Safari の色選択では数値の入力が **RGB のみで、HEX（例: `2B2B2B`）を直接打ち込めない**ことが分かった。

一方、キャプション帯の3行目（要件定義書§3.5-2）や README の確認手順は色を HEX で表記している。
そのため、「キャプションや資料に書かれた色を見て、同じ色を入れ直す」ことができず、入力と表記が揃っていなかった。
v24.1 の画面は HEX を「表示」するだけで、要件定義書§4.4 もそのとおりに定めていた（コードの不具合ではない）。

## 決定内容

- 麻地の色・金属の色それぞれに **HEX 入力欄**を設ける（要件定義書§4.4「HEX入力欄の規則」）
  - `#RRGGBB`・`RRGGBB` のどちらでも受け付ける。大文字・小文字は問わない。前後の空白は無視する。3桁の短縮形は受け付けない
  - 判定は前後の空白を除いた後に行い、入力欄の文字数は 6〜7 文字に制限しない（空白つきの貼り付けで末尾が切れないように）
  - 入力中は正しい6桁になった時点で反映し、確定時に不正なら案内文を出して直前の色に戻す
  - 色選択UIと同じ状態変数を書き換え、双方向に連動する（後から操作した方が有効）
  - 色が指定されていないときは空欄とし、薄い文字（placeholder）で標準の値を見本表示する
  - iPad 向けに自動の大文字化・自動修正・スペルチェックを止める
- 検収テスト T-18 を追加し、Step 5 の完了条件を T-11〜T-18 とする
- **版は v24.1 に含める**（タグ付けの前に取り込む）

### 版の付け方の判断

要件定義書§5.2 では、3桁（`v24.1.1` など）は「仕様は変えず、コードを仕様に合わせる不具合修正」、
2桁は「設計書に新しい機能・画面を追加する機能追加」と定めている。
今回は §4.4 に新しい入力欄を加える**仕様変更**であり、3桁の定義に当てはまらない。
また v24.1 のタグはまだ付けておらず、v24.1 の機能の実機確認の途中で見つかった使い勝手の不足であるため、
同じ機能の一部として v24.1 で完成させる。タグは HEX 入力欄を含めた実機確認が済んでから付ける。

## 却下した案とその理由

| 案 | 却下の理由 |
|---|---|
| R・G・B の3つの数値入力欄を自前で追加する | iPad の色選択がすでに RGB の数値入力を備えているため、入力手段が二重になる。HEX と数値の変換も2か所で持つことになる |
| 色が未指定のとき、入力欄に既定で標準の値を入れておく | その値を確定しただけで「色を指定した」扱いになり、キャプションに色が出てしまう。未指定（`null`）と、標準と同じ色を指定した状態が区別できなくなる |
| 3桁 `v24.1.1` の修正として出す | §5.2 の定義では3桁は仕様を変えない修正であり、設計書を変える今回の変更と食い違う |
| 別の機能追加 `v24.2` として出す | v24.1 にまだタグを付けていない段階で分けると、HEX で入力できない v24.1 を一度確定させることになり、分ける利点がない |
| 入力欄の文字数を `maxlength="7"` で制限する | 前後の空白を無視する規則と両立しない。空白つきで貼り付けたときに末尾が切れ、正しい値が6桁にならなくなる |

## 実装時に追加で決めたこと（2026-11-22 追記）

### 色が指定済みのときに空欄で確定した場合

当初の仕様は「色が未指定（`null`）のとき、空欄で確定しても `null` のまま」だけを定めており、
色が指定済みのときに入力欄を空にして確定した場合の扱いが決まっていなかった。

| 案 | 評価 |
|---|---|
| **色を変えず、表示を直前の色に戻す。案内文は出さない（採用）** | 入力欄を一度空にして打ち直そうとして、途中で離れてしまった場合でも、指定した色が消えない。色を戻す操作は「標準に戻す」「金・銀に戻す」ボタンに一本化され、役割が分かりやすい。空欄は「誤り」ではないので案内文も出さない |
| 空欄で確定したら標準（`null`）に戻す | 打ち直しの途中で入力欄から離れただけで、指定した色が消えてしまう。戻すボタンと同じことが2つの操作でできることになり、意図しない解除が起きやすい |

### 入力の誤りで出た案内文の消去

検収（T-18④）で、HEX 入力の誤りで出た赤い案内文が、その後に空欄で確定しても、色選択UIで正しい色を選び直しても残り続けることが分かった。
誤りが解消された後も赤い案内文が残ると、利用者がまだ誤りがあると受け取ってしまうため、
**空欄での確定、または色が正しく変わった時点（色選択UI・HEX入力・スポイトのいずれか）で案内文を消す**こととした。
スポイトの「○○の色を…にしました」は、色を設定した後に表示し直すので消えない。

### iPad 向けの指定の追加

自動の大文字化・自動修正・スペルチェックの停止に加え、`autocomplete="off"` を付けた。
入力欄に過去の入力の候補が出て、誤って選ばれるのを防ぐため。

## 範囲外として残したもの

- **マット・面金の色選択も `<input type="color">` だけで、HEX を打ち込めない**。今回はライナー・入子だけを対象とし、
  **マット・面金の HEX 入力は v24.2 以降の候補**とする

## 影響範囲

- 要件定義書: §4.4（表の2行の差し替えと「HEX入力欄の規則」の追加）、§6（Step 5 の完了条件を T-11〜T-18 に）、§7（T-18 の追加）、§7.3（iPad の確認項目の追加）
- CLAUDE.md: Step 5 の完了条件を T-11〜T-18 に
- コード（実装時）: 色指定欄の HEX 表示を入力欄に置き換え、判定と連動の関数を追加する。
  描画処理（麻地・金属の配色・`renderFraming`）とキャプションは変更しない。色が未指定のときの状態変数は `null` のままなので、
  既定状態で v24.0.1 と画素一致することは変わらない（T-11 を再実施して確認する）
